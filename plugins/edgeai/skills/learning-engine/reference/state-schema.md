# Edge AI Academy: State Schema

This is the single source of truth for how learner progress is stored. Every command and agent reads and writes through this schema. Get it right and the academy remembers everything across sessions, machines, and reinstalls.

## Where state lives

```
STATE_DIR = ${EDGEAI_ACADEMY_STATE:-$HOME/EdgeAI-Academy}
```

Resolve `STATE_DIR` from the `EDGEAI_ACADEMY_STATE` environment variable, defaulting to `$HOME/EdgeAI-Academy` when unset. The default must find the learner's progress no matter what directory Claude Code was launched from. It is separate from the plugin code, so reinstalling or updating the plugin never touches progress. Set `EDGEAI_ACADEMY_STATE` to relocate it (for example into a cloud-synced or backed-up folder, or an isolated directory for testing). All file paths below are relative to `STATE_DIR`.

Files:

```
~/EdgeAI-Academy/
├── learner-profile.json     # who they are, their level, their preferences
├── curriculum.json          # their personalized path (the machine source of truth)
├── curriculum.md            # human-readable mirror of the path (open it anytime)
├── progress.json            # XP, level, streak, badges, global counters
├── scorecard.md             # written once, at certification (see learning-engine)
└── sessions/
    └── 2026-08-28.md        # one journal entry per learning day
```

## Golden rules for writing state

1. **Read before you write.** Always read the existing file, modify the object in memory, write the whole thing back. Never blind-overwrite. Losing progress is the one unforgivable bug.
2. **Write valid JSON.** No trailing commas, no comments inside the `.json` files. If you are unsure, re-read what you wrote.
3. **Keep `curriculum.md` in sync with `curriculum.json`.** Whenever unit status changes, regenerate the markdown mirror from the JSON.
4. **Dates are ISO `YYYY-MM-DD`.** Use the current date from the session context; never invent dates. `lastSessionDate` and all spaced-rep dates are calendar dates (date-only), because streak and due-review logic compares whole days. A `lastUpdated` field may carry a full ISO-8601 timestamp if finer granularity is useful.
5. **If a file is missing, the learner is new.** Absence of `learner-profile.json` means run onboarding.

## learner-profile.json

Written once at onboarding, updated whenever a re-assessment happens or preferences change.

```json
{
  "name": "Jordan",
  "createdAt": "2026-08-28",
  "lastUpdated": "2026-08-28",
  "goal": "Become an Edge AI Certified consultant.",
  "specificAims": [
    "Explain AI to a business owner with confidence",
    "Run a client engagement start to finish"
  ],
  "preferences": {
    "pace": "1hr",
    "vibe": "fun-but-sharp"
  },
  "levels": {
    "M1-how-ai-works": 1,
    "M2-claude-code": 0,
    "M3-edge-ai-method": 0
  },
  "gaps": [
    "Thinks an LLM looks answers up in a database",
    "Has never opened a terminal or Claude Code"
  ],
  "strengths": [
    "Explains ideas clearly in plain language",
    "Real sales experience with small-business owners"
  ],
  "assessments": [
    {
      "date": "2026-08-28",
      "itemsAsked": 9,
      "summary": "True beginner on the tech, strong communicator. Start at u1 and lean on the communication strength.",
      "transcriptRef": "sessions/2026-08-28.md"
    }
  ]
}
```

The `levels` map drives curriculum compression. A module at level 4+ is compressed to confirmation checks (which still award XP when passed). A module at 0 to 2 is scheduled for full teaching. A1 and C1 are never compressed.

## curriculum.json

The machine source of truth for the learning path. Generated by the `curriculum-architect` agent, updated by the daily loop as units progress.

```json
{
  "generatedAt": "2026-08-28",
  "lastUpdated": "2026-08-28",
  "version": 1,
  "units": [
    {
      "id": "u1",
      "module": "M1-how-ai-works",
      "title": "What an LLM really is",
      "summary": "Prediction engine, not a database. The anchor analogy for everything.",
      "prereqs": [],
      "liveResearch": false,
      "xpValue": 50,
      "estMinutes": 35,
      "masteryCheck": "Explain to a skeptical business owner what an LLM actually is and why it is not a database.",
      "status": "available",
      "masteryScore": null,
      "attempts": 0,
      "firstTryMastered": null,
      "masteredOn": null,
      "spacedRep": {
        "interval": 0,
        "ease": 2.5,
        "reps": 0,
        "nextReview": null
      }
    }
  ]
}
```

**Status transitions:**
- `locked` -> `available` when all `prereqs` are `mastered`.
- `available` -> `in-progress` when the unit's lesson starts.
- `in-progress` -> `mastered` when the mastery check passes the threshold.
- A `mastered` unit becomes due for review when `spacedRep.nextReview <= today`.

## progress.json

Gamification and global counters. Updated at the end of every unit and every session.

```json
{
  "xp": 450,
  "level": 3,
  "rank": "Operator",
  "certified": false,
  "certifiedOn": null,
  "streak": 4,
  "longestStreak": 4,
  "lastSessionDate": "2026-08-28",
  "totalMinutes": 215,
  "unitsMastered": 6,
  "badges": [
    { "id": "first-blood", "label": "First unit mastered", "earnedOn": "2026-08-28" }
  ],
  "history": [
    { "date": "2026-08-28", "minutes": 55, "unitsMastered": 2, "xpEarned": 125, "reviewsDone": 0 }
  ]
}
```

`certified` flips to true only when BOTH certification conditions hold (Level 10 and C1 passed); set `certifiedOn` at the same moment, then run the certification sequence (scorecard + email) from the learning-engine SKILL. See the XP, rank, streak, badge, and certification rules there.

## scorecard.md

Written once by the coach at certification, per the learning-engine's certification sequence. One page: name, date, placement per module, units mastered with scores and attempts, first-try count, time span, total minutes, and the C1 capstone verdict. This file is what gets emailed to Alex.

## sessions/YYYY-MM-DD.md

A short human-readable journal for each learning day. Append, do not overwrite, if multiple sessions happen in one day. Used for continuity ("here is what we did last time") and for spaced review context.

```markdown
# Edge AI Academy: 2026-08-28

## Session 1 (55 min)
- Covered: u1 (what an LLM really is), u3 (tokens and context windows)
- Mastered: u1 (92%, first try), u3 (88%, 2 attempts)
- Struggled with: the difference between tokens and words. Re-taught with the word-chunks analogy, clicked.
- XP earned: 125. Streak: 4 days.
- Next time: quick review of u1, then u2 (how a model gets made).

## Reflection
Jordan's plain-language instinct is a real asset. Push the teach-backs harder; they are close to client-grade already.
```

## Robustness checklist before any state write

- [ ] Did I read the current file first?
- [ ] Is the JSON valid (no trailing commas)?
- [ ] Did I update `lastUpdated` / `lastSessionDate`?
- [ ] If unit status changed, did I regenerate `curriculum.md`?
- [ ] Did I use the real current date, not a guessed one?

Field notes (do not copy comments into real JSON; the real files must be pure JSON):
- `preferences.pace`: 1hr | 30min | sprint. `preferences.vibe`: fun-but-sharp | full-game | minimal.
- `levels`: one entry per module key; scale 0 unknown, 1 novice, 2 advanced-beginner, 3 competent, 4 proficient, 5 expert. Most new hires place 0 to 1 across the board; that is normal.
- `liveResearch`: true only for u4, u6, u7 (lesson-builder must web-search at teach time). `xpValue`: 50 for teaching units, 75 for a1 and c1.
- `status`: locked | available | in-progress | mastered. `masteryScore`: 0-100, last mastery-check score. `firstTryMastered`: true if mastered on first attempt. `masteredOn`: date.
- `spacedRep`: `interval` days until next review, `ease` SM-2-lite ease factor, `reps` successful consecutive reviews, `nextReview` date set after first mastery.
